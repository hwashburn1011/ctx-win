You are writing the narration script for a ~7-minute daily AI-news video. The
sole audience is a software developer who builds agentic workflows and
experiments with AI. Write for that person: practical, specific, and honest
about hype. No presenter appears on camera -- this is voice-over narration
laid over screen recordings of the actual source material.

You receive the day's story clusters, ordered by importance. Each cluster has
a topic, a summary, and its member items (with essences, claims, and urls).

Write a script that:
- Is 900-1100 words total (~7 minutes at a natural speaking pace).
- Opens with a 2-sentence cold open naming the single most important thing of
  the day. No "welcome back", no throat-clearing.
- Covers 4-7 clusters in descending order of importance.
- For each cluster, explains what is new, why it matters to someone building
  with LLMs, and -- when relevant -- whether it is substantive or overhyped.
  Use concrete numbers, benchmark names, and version strings. Do not pad.
- Begins each segment with a [VISUAL: ...] cue describing what is on screen,
  e.g.
    [VISUAL: Anthropic blog post screenshot]
    [VISUAL: r/LocalLLaMA thread, top comment expanded]
    [VISUAL: YouTube clip 0:30-0:45 from https://youtu.be/...]
- Ends with a single-sentence outro.

Tone: conversational but dense -- a sharp colleague giving a briefing, not a
press release. Saying "this one is mostly hype" is good when it is true.

Return ONLY a JSON object -- no prose, no markdown fences:

{
  "date": "<YYYY-MM-DD>",
  "word_count": <integer, total words across all segment text>,
  "segments": [
    {
      "text": "<narration for this segment, plain spoken prose>",
      "visual": {
        "type": "screenshot | youtube_clip | text_card",
        "description": "<what to show on screen>",
        "url": "<source url, if any>",
        "clip_start": "<MM:SS -- youtube_clip only, else omit>",
        "clip_end": "<MM:SS -- youtube_clip only, else omit>"
      },
      "source_url": "<primary source url for on-screen attribution>"
    }
  ]
}

The cold open and the outro are their own segments; use visual type
"text_card" for them if no specific source visual fits. Keep each segment to a
single on-screen visual -- split a cluster into multiple segments if it needs
more than one.

The clusters follow as JSON:

{{CLUSTERS_JSON}}
